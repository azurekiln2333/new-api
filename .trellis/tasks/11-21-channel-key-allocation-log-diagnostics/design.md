# 集成设计

本文件收敛子方案的接口和边界。配额的统计单位沿用站内结算，渠道手填预算与上游余额分列。正文可关，采用子方案的大小、权限和保留策略。

## 条目身份与路由

新增稳定 Key 条目 ID，按原索引逐条迁移现有凭据、用户和模型范围。多个相同凭据仍有不同 ID。通过条目 ID 和配置版本处理增删改、并发编辑、路由选择、自动禁用、余额和模型发现写回、异步任务及日志上下文。凭据状态与分配权限分别建模。插件托管账户保留原身份与刷新约束。

用户绑定入口继续优先于普通分组。公开 Key 继续受渠道和分组模型限制，个人绑定 Key 受该用户、渠道、Key 和令牌限制。先筛可用条目再构建两种模型列表，且不让额度读失败扩大模型权限。保留用户使用分组对应的计费口径。

## 共用预算

渠道/Key 共用一套主库账本。使用 channel_budget_accounts、channel_budget_reservations、channel_budget_reservation_items，由一次上游尝试引用稳定渠道/条目身份。一个事务校验配置版本、绑定、预算和预留，以既有计费预估为准入量，两层有额度时均需通过。每次重试绑定自己的预留。拒绝的候选由现有路由尝试其他合法候选；无法可靠预留时返回可重试错误，不能当成无限额度。

成功和按原计费规则会计费的失败按实际记账，取消及无费用失败释放。异步任务保存预留 ID，确保跨节点调价、退款和重试幂等。实际费用可能高于预估，实际用量照实记入，剩余显示耗尽，后续准入拦截。余额、订阅和令牌继续由现有计费流程处理。预算操作不引入新定价。对已有渠道/条目用量从账本上线开始计，避免用异步 UsedQuota 列回填或与上游 USD 快照混算。

预算改额保留用量和预留。重置仅清当期用量并切换周期，正在执行的请求仍持有预留，完成后计入新周期。此前已结算的旧周期退款只影响历史累计。去重比较凭据及完整有效限制，预览并确认后存一份限额，累计已用额度，跳过仍有活跃请求或任务的候选。退休条目保留历史身份，后续合法调整按合并关系和结算周期归属。配置修改、准入、重置及去重共用锁顺序。

手填渠道预算与现有上游 Balance 分别读写和展示。没有余额查询能力时仍显示本地预算并允许编辑。本地渠道预算对公开和绑定请求统一生效，额度耗尽后选择其他合规渠道。

## 请求日志

在请求正文首次读取时冻结原始提示字段，早于协议改写和插件。消费与失败日志只记录实际处理节点和轻量正文引用，一次请求重试共享快照。异步结算保留原请求及提交节点，同时记录结算执行节点。兼容现有开关和显式错误排除。未读取、不可解析、截断、存储故障、旧记录都显示真实状态。

详情存到实际 LOG_DB。列表不拉取大段正文，仅在打开详情后由管理端按稳定引用和记录权限读取。使用现有管理日志权限和 PAT log:read，不向普通列表、导出和进程日志附带正文。按关联日志和活动任务引用有界清理，独立日志库使用持久化写删保护和可恢复标记，不能假定存在跨数据库事务。详情保存失败不改变业务响应及计费。

## 上线及性能

先在所有共享节点部署能识别新条目和账本的版本，确认迁移成功后统一启用重复条目和额度。拒绝旧配置写入覆盖新字段。账本激活后，每次尝试增加主库事务，不限额账户也跟踪用量，便于之后加限额时保留在途预留。验证 HK–US 启用前后的往返次数、首包时间和日志写入开销。启用重复条目后的正常回退目标是仍支持新条目的修正版。退回不支持新条目的旧版本需要单独验证恢复方案，避免丢失用户绑定、限额或在途结算。

实现细节见[条目与账本](../11-21-key-allocation-quotas/design.md)、[手工渠道预算](../11-21-channel-manual-balance/design.md)和[日志](../11-21-request-log-body-node/design.md)。

### 账本首期上线约束

启用账本前必须在所有服务节点关闭 `BATCH_UPDATE_ENABLED`，停止并排空旧节点及其待写批次。启动和请求准入均检查这一条件，不能把只在内存排队的用户或令牌预扣当成已经持久化。未启用账本的部署保持原有批量写入行为。

首期账本对 `/v1/realtime` 在客户端升级及上游连接前返回明确的本地 503，包含不限额账户和数据库已激活但进程开关关闭的情况。该协议的自动生成工作尚无逐次预算准入；此限制不影响 HTTP 或 Responses WebSocket，也不代表修复了旧 Realtime 的累计结算问题。

异步任务受理后，以一个主库事务保存任务、用户或订阅与令牌差额、正文关联以及待完成的账本结算目标。实际费用高于估算也必须入账。提交确认丢失时，只有有界读取到匹配的持久任务和预留后才能确认提交结果；仍不确定时保留扣费与预留，禁止延迟清理执行退款。账本重放只完成预算结算，不再次扣费或投递缓存差额。普通缓存发布只在成功提交后调用一次，不宣称 SQL 与 Redis 具备原子投递保证。

## R8：控制台 429 隔离

原有 CT 按 ClientIP 在注册、登录、刷新、退出和其他控制台操作间共用，默认 20 次/1200 秒。保留现有阈值与 IP 防护，将注册、刷新、退出和控制台操作拆成静态业务作用域；密码、MFA、Passkey、OAuth 和密码恢复继续共用原 CT 登录计数。外层 GA 聚合计数、邮件验证和已认证用户限制保持有效，不以客户端 Cookie 或会话声明扩大匿名额度。

通用拒绝返回 HTTP 429、Retry-After 及 RATE_LIMIT_EXCEEDED/message_key 标准错误。前端共享错误转换保留具体后端错误，仅对空响应或 HTML 429 使用已有七语 Too many requests 文案。真实路由与内存/Redis 测试覆盖跨业务隔离、登录别名不可绕过和 GA 聚合上限。线上代理是否错误合并 ClientIP 尚无部署证据，不把代码复现当成已确认的线上配置结论。
