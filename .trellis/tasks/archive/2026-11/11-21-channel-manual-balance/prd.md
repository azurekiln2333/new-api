# 渠道本地额度

本方案对应父任务 R4，随父方案统一审阅。管理员可为每个渠道设置站内总额度，包括上游未提供余额查询接口的渠道。

## 行为

- 渠道额度默认不限额。管理员可启用上限、修改金额、恢复不限额或单独重置渠道本期已用值。
- 渠道额度由该渠道所有成功结算的公共和绑定 Key 请求共用，使用站内实际计费金额。启用后，已用和在途预留达到上限的渠道停止接收新请求。请求预估用量超过可用额度时按其他可用候选回退。
- 渠道及 Key 各自消耗同一笔实际结算量。渠道总额和 Key 分配额分别约束路由。用户余额和令牌额度按原请求照常结算。
- 编辑上限保留已用及预留。重置只清空对应额度的本期已用值，保留在途预留和累计用量。进行中的请求按完成时所属期结算，旧期退款只修正旧期及累计用量。
- 列表提供渠道本地额度状态，详情提供总额、已用、预留、可用额及起算时间。已有上游余额查询及快照独立维护。

## 验收

- 无上游余额接口的单 Key 和多 Key 渠道均可操作，刷新后读到保存值。不限额与启用零额度可区分，非法金额被拒绝。
- 多节点同时使用不同 Key 时共用渠道总额。耗尽时回退或提示额度不足，提额和重置后恢复可用。实际费用超过预留时按实际入账，后续请求受剩余额度控制。
- 预留、失败释放、在途重置和旧期退款保持一致。渠道重置和 Key 重置独立，原请求账单及历史统计保留。
- 上游余额刷新、局部权限变更和一般渠道编辑不会覆盖本地额度设置。SQLite、MySQL、PostgreSQL 通过实际迁移和行为验证，前端覆盖七种语言。

## 交付依赖

先由 Key 分配子任务完成共享额度账本、请求尝试生命周期和路由判定。此子任务负责渠道管理接口与界面。上游实际成本对账及跨区域部署优化不在本任务范围内。
