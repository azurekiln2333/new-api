# 渠道本地额度设计

## 账本与路由

使用共享额度账本。账户以 `(scope_type, scope_id)` 唯一标识，渠道域为 `channel`，ID 为 `Channel.Id`。关键字段为 `enabled`、`limit_quota`、`period_used_quota`、`lifetime_used_quota`、`reserved_quota`、`reset_epoch`、`config_version`。金额用整数站内额度。`lifetime_used_quota` 表示起算后经退款和调价修正的净用量。共享方案见 [Key 分配子任务](../11-21-key-allocation-quotas/design.md)。

每次实际转发使用一个持久化尝试预留。共享事务按渠道配置、渠道额度账户、按 ID 排序的 Key 额度账户、尝试记录及明细的顺序加锁。两个账户原子检查并预留同一个预估金额。如此任一上限不足都不会留下单侧扣减。后台任务执行、重试、退款和补结算沿用共享生命周期和尝试标识。

启用上限时，可用额为上限减去本期已用和在途预留，界面最低显示 0。可用额为 0 时，即使预估为 0 或模型免费，新请求也不使用该渠道。可用额为正时，确认预估能覆盖才转发。实际超过预留的已发生消耗据实计入，允许账户显示超额并停止新请求。渠道和 Key 各更新自身计数，账单金额仍是一次现有用户及令牌结算。

路由可批量读取概要筛选候选，绑定路由、公共路由、指定渠道和模型列表复用相同的额度可用规则。权威校验以尝试事务为准。额度耗尽不修改渠道开关和探测状态，按既有无可用候选路径回退。跨节点缓存仅加速发现，不参与扣减和额度行政更新。

## 管理操作

建议路由为 `GET /api/channel/:id/quota`、`PUT /api/channel/:id/quota`、`POST /api/channel/:id/quota/reset`。通过现有渠道路由注册器分别执行对应渠道的 `ChannelRead` 和 `ChannelOperate` 权限，沿用现有会话、来源和管理令牌范围校验。接口与操作审计仅携带操作者、渠道 ID、金额和版本等必要字段，沿用项目的认证及防泄露约束。

- 读取调用 `ReadChannelBudget`，返回额度是否启用、上限、本期已用、累计已用、预留、剩余、起算时间、配置版本及重置代数。不限额时剩余值缺省。渠道列表批量返回摘要以免逐行请求。
- 修改调用 `SetChannelBudgetLimit`，仅接收 `enabled`、`limit_quota`、`expected_config_version`。校验整数、非负、前端安全整数及账本计算上界，不能把溢出或小数静默转换成有效值。缺省账户视为不限额，首次显式配置用共享事务创建。更改上限保留计数，配置版本仅因管理更改递增。
- 重置调用 `ResetChannelBudgetUsage`，接收 `expected_config_version` 和 `operation_id`。清零本期已用并增加代数和配置版本，保留累计净用量和活跃预留。同一操作 ID 重放返回原结果。过期版本返回冲突及刷新入口。新期的结算不会被旧期的退款抵销，渠道和 Key 分别判断所属期。
- 单 Key 渠道套用同一渠道账户。相同凭据在多个分配项或渠道的上游实际成本不合并为全局预算。

## 界面

在渠道列表和行操作增加独立本地额度入口，始终按操作权限显示，与上游能否查余额无关。额度弹窗使用现有 `Dialog`、`ConfirmDialog`、额度格式化和输入控件，列表概要复用 `QuotaDetailsPopover`。现有 `BalanceQueryDialog` 有原始响应和 Codex 专用分支，保留其上游职责。复用通用组件，渠道额度表单只实现对应 API、状态和版本冲突处理。明确金额采用站内计费展示单位，换算使用既有 `@/lib/format`、`@/lib/currency`，界面语言经 `toIntlLocale` 后交给格式化方法。使用现有 query keys 收敛成功后的详情、渠道列表与相关可用模型查询刷新。

## 上线和恢复

主库新增账本保留 `Channel.Balance`、余额明细和 `Channel.UsedQuota`。共享账本开始时从零统计，显示 `accounting_started_at`。上线前所有节点升级，再暂停新请求并排空同步在途，随后一致开启账本。此前异步任务保留原流程，不补入新账本。只有一致启用后开放限额操作。

账本启用后，不限额账户仍依共享规则持久记录尝试，保证随后启用上限时考虑在途消耗。权威账本不可用时按服务错误处理，不能绕过门禁继续转发。共享数据库多一次请求前事务及结算写入，须在现有 HK→US 链路验证额外往返与锁持有时间。各阶段不得将行锁持有到上游请求结束。

激活后采用兼容的修复版本恢复运行，保留账本及在途结算责任。回到旧版需要暂停流量、处理在途尝试并按共享方案从审阅过的备份协调恢复。账本、迁移及其功能开关由共享生命周期实现负责。
