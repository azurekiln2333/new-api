# 渠道本地额度实施清单

1. 在父方案完成统一审阅后开始。以 Key 分配子任务的共享账户、尝试预留、结算和上线开关为前置，读取其设计及本任务上下文。确认两种范围使用同一额度生命周期，服务错误、耗尽、重置和启动行为一致。
2. 在 `router/channel-router.go` 和渠道控制器中注册三个接口。以共享额度模型事务实现读取、更新上限及重置，使用现有授权、错误和审计方法。覆盖不存在渠道、无操作权限、账本尚未启用、无效金额和过期版本。渠道列表及搜索使用批量额度摘要。一般编辑接口和上游查询继续使用原字段写入范围。
3. 在 `web/src/features/channels/` 补充类型、API 和 query keys，接入渠道列表、行操作和本地额度表单。组合已有的 `Dialog`、`ConfirmDialog`、`QuotaDetailsPopover` 和金额工具。提供不限额、零额、修改、重置及版本冲突后的刷新状态。打开表单时读取实时摘要，写入后刷新相关查询。沿用上游查询和 Codex 余额入口。使用 i18n 技能处理新增的七语文案，依赖现有可访问表单规范。
4. 扩展渠道余额管理测试，给出通过权限校验的额度写入、越权拒绝、过期更新、上游刷新互不覆盖及无余额查询 API 时的读写用例。共享子任务负责原子预留、退款、重试、超出预留的实际录入、独立重置、模型可见与混合预算的集成覆盖。扩展现有渠道余额及行操作测试，并覆盖表单保存、编辑、重置、冲突回读和无上游查询接口。
5. 在主库新建及近期发布版本的代表性数据库上各执行启动迁移两次。验证逐项初值、历史渠道余额和已用统计，并在真实 SQLite、MySQL、PostgreSQL 上执行渠道与 Key 共用额度的并发准入、实际结算、失败释放及重置测试。使用 CI 的 MySQL 8.4、PostgreSQL 16 配置和 SQLite 默认测试库。若选择依赖版本特性的实现，补测最低支持版本。跨区域部署模拟验证每次请求的新增数据库往返和同渠道竞争。记录实际测试版本、执行命令及结果。
6. 检查后提交父任务集成验证。回滚按共享子任务的停止准入及在途结算步骤执行，保留账本数据。渠道 UI 可随账本功能开关关闭。

## 验证命令

- 后端使用 `gofmt` 格式化变更文件。配置 `TEST_MYSQL_DSN` 和 `TEST_POSTGRES_DSN`，运行 `go test -p 1 -count=1 ./controller -run 'TestChannelBalanceManagementDatabaseMatrix|TestChannelQuota'`，共享测试命令按 Key 分配子任务。旧渠道行为回归沿用 CI 中 `TEST_CHANNEL_SQL_DSN` 的逐库运行方式。
- `web/` 下运行 `bun check -b`、`bun run test -- src/features/channels/components/__tests__`、`bun run lint`、`bun run format:check`、`bun run build`，执行 `bun run i18n:sync` 及该技能规定的七语核验。
- 检查各数据库测试均已实际执行。记录迁移前版本、迁移两次的结果及计数与原余额保留的证据。未执行的环境在交接中单独列出。
