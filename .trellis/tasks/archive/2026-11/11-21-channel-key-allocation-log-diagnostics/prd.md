# 渠道 Key 分配、手填额度与通用日志

## 目标

同一渠道里的同一个上游 Key，可以公开给渠道分组，也可以另建条目单独分给指定用户。管理员能分别管理额度和模型权限，并在通用日志中查到原始提示和处理节点。

## 需求与验收

| 编号 | 行为与验收 | 子任务 |
| --- | --- | --- |
| R1 | 同一凭据可以同时存在公开条目及分别绑定用户甲、乙的条目。追加、重排、删除、启停和发现模型均不能错配绑定或限制。绑定用户可以跨组调用个人条目，其他用户仍走普通分组路由。 | 独立 Key 分配 |
| R2 | 每个条目支持不限额、设置和更改总额、单独重置已用。用户余额及令牌额度照常扣，重置不退费或修改历史。站内用量独立计算。并发请求先预留额度，实际结算超过预留时照实记账并阻止后续准入。编辑和重置不清掉在途预留。 | 独立 Key 分配 |
| R3 | 多 Key 管理页提供预览并主动去重。凭据、绑定身份、权限、额度和模型等配置完全等价才可合并。预览显示合并后的用量，保留历史，跳过在途或还有未完成任务的条目。 | 独立 Key 分配 |
| R4 | 无上游余额查询接口的渠道也能手工填写并刷新后读回额度。提议按站内用量作为本地预算，耗尽后跳过该渠道。上游查询结果单独展示，不能覆盖本地预算。 | 渠道手填额度 |
| R5 | 同一个跨组绑定用户在 /v1/models 和控制台看到个人条目实际允许的模型，并能请求这些模型。其他用户不可见。更新绑定、模型限制或耗尽和重置额度后验证两处列表与实际路由一致。保留原令牌模型限制。 | 独立 Key 分配 |
| R6 | 在已有开关允许记录的成功与失败日志详情显示客户端原始 prompt/messages，以及同协议的对应提示字段。覆盖已经读取正文的鉴权后最终拒绝及上游尝试失败。插件修改请求后仍可查原文。正文独立保存，管理端按需读取。提议默认开启并提供开关，单请求默认上限 256 KiB，截断状态可见，随日志和活动任务引用清理。 | 通用日志 |
| R7 | 通用日志管理列表及详情显示实际处理实例的 NODE_NAME。异步处理节点与原始提交节点可分别查看。历史未知值显示未记录。 | 通用日志 |
| R8 | 排查登录、注册、邀请注册低并发返回 429，以及模型 API 调用影响控制台的问题。确定每层限流的计数身份、路由范围和代理真实 IP 处理；修复可复现的错误共享计数或错误路由。保持匿名登录防爆破和注册防滥用，验证不同来源、认证身份及模型/控制台路由的隔离。 | 集成追加排查 |
| R9 | OpenAI 类型渠道根据管理员路由配置，向上游 `/v1/messages` 发送转换后的请求；普通及流式响应转换回客户端协议，保留错误、工具调用和用量结算语义。复用已有路由和协议转换能力，不凭模型名称猜测上游接口。 | 集成追加路由 |
