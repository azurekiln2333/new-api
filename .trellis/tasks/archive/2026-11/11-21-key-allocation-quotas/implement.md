# Execution and verification plan

## Implement in dependency order

1. Read root and web AGENTS, billing rules, relevant Trellis specs and the existing Key scope task before editing. Verify the current OWASP ASVS version and applicable Authentication, Session Management, Authorization and Logging guidance before changing selection or management authorization. Capture the applicable controls and validation. If task plugin host behavior is touched, read `docs/plugin-api/v1.md` in full and inspect the contract files where applicable.
2. Add allocation and budget models/migrations in `model/`. Backfill original indices under current channel locks using a durable channel marker. Preserve legacy readers during the migration window. Build test fixtures for repeated, missing and disabled credentials, model restrictions and user bindings. Expose the shared budget account API for the manual channel budget task.
3. Implement transaction-backed limits, reserves, settlement revisions, resets, merge aliases and recovery. Hook configuration and projection writes into the allocation-aware channel transaction and existing cache refresh. Validate limits and administrative expected versions on the server. Use cross-dialect rows and indexes with inspectable rewrite and locking behavior.
4. Make every management and selection path allocation-aware. Start with `controller/channel.go`, `model/channel.go`, `model/channel_plugin_credential.go`, `controller/channel_upstream_update.go`, `service/channel_select.go` and channel context/metadata. Trace Create/Update, append, delete, reorder, disable, probes, model apply, credential refresh/import, usage reads and caches. Preserve token model ACL, user binding priority, public routing and group pricing. Keep secrets masked in all management and error responses. Add ID-aware multi-Key management requests, quota reads and writes, reset and dedup preview/apply.
5. Wire attempt holds at the upstream send boundary and finalize with the actual existing station amount. Trace `controller/relay.go`, `relay/request_billing.go`, `service/billing.go`, task submission/polling and transport-specific entry points. Persist task references before transferring the request hold. Verify free, streaming partial delivery, image repricing, policy fee, retry, Playground, Responses WebSocket and Realtime paths. Keep reserve, settlement and task callback failures diagnosable and retry without replaying wallet/token mutations. Coordinate the forwarding reservation contract with the manual budget child and metadata with the log diagnostics child.
6. Extend `controller/model.go` and `controller/user.go` list paths. Apply current policy and budget eligibility in set-oriented reads, keep response compatibility and test both model surfaces for revocation/projection lag. Confirm selection cannot bypass access or budget snapshots taken for listing.
7. Read `web/AGENTS.md` and load the shadcn, React and i18n skills for the UI. Extend `web/src/features/channels/components/dialogs/multi-key-manage-dialog.tsx`, feature types/API wrappers and cache invalidation. Reuse `ConfirmDialog` and quota display/formatting. The existing user quota dialog targets user APIs, so compose existing controls with channel-specific operations. Add used/remaining, limit changes, independent reset and preview/apply. Translate each new source string in all seven locales, including backend messages the console translates.
8. Verify and document rollout activation for all nodes and existing tasks. Use a dry-run or isolated migration fixture before any production adoption. Review the ledger's additional write and round-trip cost on a representative remote node. Product work and production activation are separately controlled.

## Behavior to verify

| Area | Regression cases |
| --- | --- |
| Stable identity | Public and two bound equal Keys, duplicate append, scoped model moves, reorder and deletion, stale request or health/discovery writeback, managed-account uniqueness, caches rebuilt on changes. |
| Permission | Owner outside channel group can use allowed models, other users denied, public sibling remains public, token/model restrictions stay enforced in routing and both lists, no secret in list/reset/dedup/error. |
| Counter transitions | Separate channel/Key limits, zero and unlimited, change limit preserving period use, two-node race, failed attempt release then retry, free and trusted paths, true settlement above estimate, reset while reserved, old refund after reset, charge recorded once, stale revision/refund replay, underflow/overflow rejection. |
| Async and transport | Persisted task ID/attempt correlation, poller restart, successful repricing, actual funding failures, task retry/refund, task lifecycle after channel or entry retirement, socket turn coverage, aborted stream settlement, restart recovery with ambiguous forwarded vs definitely unforwarded attempt. |
| Merge | Equivalent settings only, compare model scope mode, skip in-flight/nonterminal, stable survivor, conserve counters, same configured cap, no channel double-count, historical adjustment after chained merges and resets. |
| Console | Scope/status eligibility updates, quota edit vs reset, dedup preview/commit conflicts, currency and JS-safe ID handling, seven locales and masked messages. |

Extend `controller/channel_multi_key_test.go` for management/races, nearby model status/availability tests where applicable and existing billing/task fixtures for actual lifecycle invariants. Any necessary new budget contract cases should be consolidated into a focused regression file. Use testify `require` and `assert`. Include backend permission checks and meaningful integration coverage where model behavior and API behavior differ. Avoid repeating the same path in each layer.

## Validation commands and evidence

- Format changed Go files. Run `go test -p 1 -count=1 -v ./model ./service ./controller ./relay/...`, targeted race checks for allocation/settlement and affected transports, `go vet ./...` and `go build ./...`. Follow the existing frontend embed setup in CI for backend commands.
- Use the real service configuration from `.github/workflows/ci.yml`. Set `TEST_MYSQL_DSN`, `TEST_POSTGRES_DSN` and `TEST_REDIS_ADDR` to isolated integration services. CI currently uses MySQL 8.4 and PostgreSQL 16. Exercise budget/model tests for each SQLite, MySQL, PostgreSQL fixture via the existing `TEST_TASK_DB_DIALECT` matrix and run relevant channel controller cases with `TEST_CHANNEL_SQL_DSN` for each SQL service. Add new test names to the matrices so tests cannot silently fall back to SQLite. Record exact engine versions and executed commands. If SQL features require minimum-supported verification, include MySQL 5.7.8 and PostgreSQL 9.6 as applicable.
- For each primary DB, verify fresh creation and an upgrade from the latest released version containing representative public, bound, duplicate and disabled entries. Preserve historical usage, keys, permissions and uniqueness. Run startup/migration twice and check IDs/counts/indexes, then real cross-connection admission and reset/settlement races. Use production-equivalent rollout steps only against isolated databases. Exercise separately configured log-store integration where affected by shared request/task metadata, coordinated with the diagnostics child.
- If an independent module or its public API changes, build from that module with `GOWORK=off go build ./...`. Do not introduce an independent module dependency on the host allocation model.
- From `web/`, run `bun run typecheck`, targeted `bun run test -- <paths>`, repository lint on updated files, `bun run build` and appropriate i18n sync/validation. Verify added keys across en, zh, zh-TW, fr, ja, ru and vi.
- Report unavailable environments and unchecked behavior explicitly. The planning artifacts do not represent executed application or migration tests.
