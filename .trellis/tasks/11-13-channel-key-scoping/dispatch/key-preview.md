# 追加 R6：多 Key 管理列表显示 key 局部信息

问题：多 key 管理对话框的列表里每行只有序号，分不清是哪把 key。

要求
- 列表每行显示该 key 的脱敏预览，用来对得上上游后台里的那把 key。
- 脱敏由后端生成，接口只返回预览字段 `key_preview`，不返回完整 key。规则：普通字符串 key 显示前 3 位 + 省略号 + 后 4 位；长度不足 12 位时只显示省略号 + 后 2 位；任何情况下显示的字符总数不超过 8。JSON 结构的 key（如 Vertex 服务账号）不要显示密钥内容，改显示其中非机密的标识字段（如 client_email 或 project_id，哪个有显示哪个），都没有就按普通字符串规则处理。
- 预览不得写入日志、审计记录、错误信息。不新增权限，沿用该接口现有的权限。
- 现有的「查看完整 key」流程（如果有）不动。
- 前端：预览用等宽字体显示在序号旁边，复用现有表格单元格/徽标写法，不新写通用组件；预览为空时显示 —；搜索或排序现有逻辑不动。
- 后端新增面向控制台的英文文案（如果有）追加到 $T/i18n/PI-1.txt；前端新增文案补齐七种语言。
- 测试：后端扩展 controller/channel_multi_key_test.go，覆盖短 key、普通 key、JSON key，并断言返回里不含完整 key；前端扩展现有测试。

分工：本次只有 na-pi-1 一个 pi 做，后端和前端都归它（字段名 key_preview 以本文件为准）；不执行任何 git 写操作；完成后在 $T/reports/R6.md 写报告（不超过 30 行：改了什么、跑了什么命令、结果）。

# 追加 R7：多密钥渠道在编辑里「显示当前密钥」，两把 key 混成一串

现象（用户原话）：新建一个多密钥渠道，进渠道编辑，点「显示当前密钥」，两个密钥被混在一起显示。

要求
- 先查清是「只是显示错了」还是「存进去就错了」：核对新建多 key 渠道后库里的 key 是否确实被拆成多把（multi_key_size 等于填入的数量），再看编辑页「显示当前密钥」的数据来源（接口返回的是什么格式）和展示控件（是不是单行输入框，把换行吞掉了，或者哪里用了不带分隔的拼接）。重点看 web/src/features/channels 下的 use-channel-key-disclosure.ts、channel-mutate-drawer.tsx 里 key 字段，以及后端返回当前密钥的那个接口。
- 修法：多 key 渠道下每把 key 单独占一行显示（多行文本或列表，与现有风格一致，复用现有组件），顺序与多 key 管理列表里的序号一致；单 key 渠道显示不变。
- 必须确认不会把混在一起的显示内容当作新 key 保存回去：编辑后不改 key 直接保存，库里的 key 列表、各 key 的状态/模型范围/绑定用户都不得变化；改 key 走现有的追加/覆盖逻辑，行为不变。如果发现库里已经存了混合的 key，写进报告，不要自动改数据。
- 补测试：后端若有改动，扩展 controller/channel_multi_key_test.go；前端扩展 channel-key-disclosure.test.tsx，断言两把 key 分行显示且互不拼接。新增文案补齐七种语言。
- 由 na-pi-1 在 R6 做完后接着做，完成情况写进同一份 $T/reports/R6.md（加「R7」一节），不用另写报告。
