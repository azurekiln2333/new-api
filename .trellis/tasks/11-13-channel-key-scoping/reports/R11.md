# R11 修正 R10：用户气泡居右、气泡内文字左对齐

## 改了什么

- `lib/message/message-layout-utils.ts`：`getMessageAlignmentClass` 由 `items-end text-right` 改为 `items-end text-left self-end`；left 分支加 `self-start`。仍由 `alignment` 驱动，`messageLayoutMode==='left'` 时用户气泡照旧靠左。
- `lib/message/message-styles.ts`：给用户气泡加 `group-[.is-user]:max-w-none`（见核实 4）。
- `lib/message/__tests__/message-layout-utils.test.ts`：删掉只断言 `items-end/items-start` 的错误契约，改为断言 right 含 `self-end`、`text-left` 且**不含** `text-right`；left 含 `self-start`。
- 新增 `components/message/__tests__/playground-message-content.test.tsx`：真实 `PlaygroundMessageContent` 放进 `<Message>` 渲染，断言用户气泡贴右 + 文字左对齐、无 `text-right`；`layoutMode='left'` 时贴左；assistant 贴左且仍 `max-w-3xl`；气泡带 `max-w-none` 覆盖。
- 未动：AI 回复宽度/对齐、内容渲染、流式、工具调用、编辑态、窄屏规则、两个宽度函数的数值。

## 核实结论

1. 成因属实：气泡根节点 `w-fit`，父列 `flex-col` 默认 stretch，带明确宽度的子项不被拉伸 → 落在列左侧；根节点的 `items-end` 只管内部子项。改 `self-end` 修好，父列与编辑态都不用动。
2. 成因属实：`text-right` 被气泡继承，多行文字右对齐，即用户说的「看着很难受」。改 `text-left`。
3. 原测试只断言 class、没量坐标，所以 R10 没发现。现以浏览器量坐标为主、class 契约为辅。
4. **疑点 4 成立**：`ai-elements/message.tsx` 的 `flat` 变体给用户气泡加了 `max-w-[80%]`，包含块是 `w-fit` 根节点，实测气泡宽 = 根宽 604.8×80% = 483.83，等于列宽 56% 而非 70%。按 dispatch 首选方案在 `message-styles.ts` 用 `max-w-none` 覆盖，共享组件未改；覆盖后长消息气泡正好 604.8 = 列宽 70%。
5. 时间/耗时行与操作按钮本来就贴气泡右边缘，实测 gap 均 0，未改。

## 浏览器实测（真实坐标，非 class 断言）

做法：`rsbuild build` 出 CSS → RTL 在 jsdom 渲染真实 `PlaygroundChat`（短用户消息「你好」+ 长 AI 回复 + 约 200 字含换行用户消息）取 `innerHTML` → 拼页引用该 CSS + 内联脚本用 `getBoundingClientRect`/`Range.getClientRects` 量数据 → 无头 Chrome 取结果。`--window-size=390` 在 `--headless=new` 下被夹到 512（实测 innerWidth=512），故改用 CDP `Emulation.setDeviceMetricsOverride` 得到真正 390 视口。临时文件已删除。
