# R8 渠道连通性测试支持选择 key

## 改了什么

**后端**
- `controller/channel-test.go`：`testChannel(...)` 新增 `keyIndex` 参数（-1 = 自动，沿用 design §8 的按测试模型选 key）。`TestChannel` 解析可选查询参数 `key_index`：非法/负数直接 400。
  - 指定 key 时先 `checkChannelTestKey` 校验：非多 key 渠道、下标越界、key 的 `MultiKeyModels` 不覆盖被测模型 → 返回本地错误（`invalid_request` / `channel_key_scope_unsatisfied`），带清楚文案（含 key 序号与模型名），**不发上游请求**。禁用状态的 key 允许测。
  - 指定 key 的测试走 `middleware.SetupChannelTestContext`，直接用该 key，不经过选 key；不再更新渠道级 `response_time`（结果只作用于被测 key）。
  - 失败归因：`testResult.keyIndex` 记录实际服务本次测试的 key（`servedTestKeyIndex`）。
- `middleware/distributor.go`：把 `SetupContextForSelectedChannel` 的渠道上下文装配抽成 `applySelectedChannelContext`（渠道 id、类型、setting、param/header override、model mapping、base URL、api_version 等原样搬移），新增 `setSelectedChannelKey` 与 `SetupChannelTestContext(c, channel, modelName, key, keyIndex)`；自动路径行为不变。
- `controller/channel-test.go` 健康检查（批量/测试全部渠道）：`testChannelForHealthCheck` 传 `-1`，行为不变；另外两处小修：响应时间超时判定只对真正发过请求的测试生效（本地错误不再被误判超时），自动恢复只在能定位到具体 key 时才按 key 恢复。

**自动禁用的实际语义（调研结论）**：`UpdateChannelStatus` 在多 key 渠道下把状态写到 `MultiKeyStatusList[被测 key]`（`handlerMultiKeyUpdate`），只有**所有 key 都不可用**时渠道才被置为自动禁用。所以 key 级测试失败本来就不会直接禁用整个渠道；`processChannelError` 通过 `ContextKeyChannelKey` 定位 key，而这个值在指定 key 路径下由 `SetupChannelTestContext` 明确写入，因此禁用只落在被测 key 上。

**前端**
- `channel-test-dialog.tsx`：多 key 渠道（`is_multi_key && multi_key_size > 1`）新增「Tested key」下拉：`自动（按测试模型选择）` + 每把 key 的选项 `序号 · key_preview · 启用/禁用`（预览来自 R6 的 `key_preview`，空则 `-`）；选中禁用 key 时显示禁用原因。单 key 渠道不显示。选中 key 不覆盖被测模型时自动回落到「自动」，避免用错 key 误判失败。
- `api.ts` 的 `testChannel` 与 `lib/channel-actions.ts` 的 `handleTestChannel` 支持 `key_index`；`channelsQueryKeys.multiKeyStatus` 新增查询键复用现有 `getMultiKeyStatus` 接口拉 key 列表。
- 新增 4 条文案（Tested key / Auto (by tested model) / 说明 / 只列出前 N 把），七种语言齐全（走 `add-missing-keys.mjs` + `i18n:sync`，脚本已删除）。

## 关键决定
- 选项以「序号 · 脱敏预览 · 状态」展示；`multi_key_size == 1` 的多 key 渠道视为无需选择，不显示下拉。
- 指定 key 测试不改渠道 `response_time`（那是渠道级指标，测单把 key 不应污染）；自动测试行为与改前完全一致。
- 批量测试调用同一条 per-model 路径：Auto 下行为与原来逐字节一致；只有显式选了 key 才会全部打在那把 key 上。
