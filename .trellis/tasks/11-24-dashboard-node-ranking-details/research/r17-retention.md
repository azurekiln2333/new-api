## Behavior boundary

- Add root-managed usage-log retention days and independent request-content retention days. Both default to 0 (keep forever); no historical deletion is enabled by upgrade alone.
- Add capture enabled/max-bytes controls to existing Log Maintenance settings; preserve `REQUEST_CONTENT_LOG_ENABLED` / `REQUEST_CONTENT_LOG_MAX_BYTES` as explicit environment overrides and existing bounds. Show override/effective state rather than claiming a saved setting defeats an environment override.
- Reuse the existing master system-task scheduler and log-cleanup handler for scheduled usage-log deletion. Preserve manual cleanup, leases and bounded deletion batches. No consume-log billing fields or arithmetic changes.
- Reuse the protected request-content reclaim path for independent expiration. Never delete a payload with an active async-task reference or live writer; preserve uncertain-operation fences and separate-log-store/ClickHouse semantics. Usage-log rows remain intact when content expires.
- Add a root-only cheap storage summary endpoint: exact table bytes only where supported with metadata queries; return unknown rather than doing expensive full-table scans.
- Evaluate compression without guessing a measured ratio. PostgreSQL already compresses out-of-line TEXT with TOAST; a new envelope/application codec would affect every historical read, cross-version task handoff and other log engines. Prefer no storage encoding/schema change in this scoped patch; document conditional estimates and a hosted sampling follow-up instead of inventing production results.
- No automatic VACUUM FULL / pg_repack. Explain ordinary deletion makes space reusable; OS-level PostgreSQL reclamation is a separate disruptive operations step.
