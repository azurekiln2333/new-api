## Ownership
pi-logs exclusively owns web dashboard/rankings/public-header/system-settings API/system-info components; instance/resource and ranking aggregation backend/controller files; related existing tests. You are not alone; preserve peer edits and request handoff before overlapping changes.
## Behavior
User clarified ALL users see CPU/memory/storage in existing overview API cards, configurable ordering and wider API area. Existing system settings binds instances to API domains; ONE instance can bind MULTIPLE configured domains. Click API item opens safe filtered node detail. Preserve complete root-only node API; public projection only approved resource/state fields, no hostname/internal addresses/sync errors. Explicit unknown/stale/disabled monitoring states. Homepage avatar desktop/mobile direct dashboard; console menu unchanged; hide admin overview onboarding all entry/reminder states, preserve installer. LLM ranking model opens existing model-square-style drawer with usage and user ranking, not pricing link. Server masking: admins full names all users; ordinary viewers full self name and masked others. No user IDs/real names in masked payload/cache. Reuse time window/auth/model filters. router/api-router.go/model/main.go owned pi-billing: send exact additions; model/log.go shared audit ownership use separate model ranking helper. Send all locale keys to pi-ui.
## Compatibility
Ranking current-name lookup remains one bounded top-20 batch. Server projection applies the parent's full/self/partial/anonymous policy before serialization; no masked IDs or hidden full-name fields. Dashboard user-quota requests consume AbortSignal and key by time range, user ID and role; live admin gating hides retained cache data after logout/demotion.
Reuse a shared extraction of the existing instance ring/value/tooltip display and the existing business Dialog. Keep overview data on the safe public projection. Only the settings selector uses the root-only instance list; gate and mask its identity-keyed cache without widening server permissions. Preserve existing missing selections and independent API-to-node associations.
Preserve existing auth scopes, revision/CAS, routing, log/audit durability and quota units. Add optional compatible DTO fields; avoid unbounded queries. Publish exact interface early. Unsafe or materially wider choices must be sent to root before editing that portion; continue independent owned work.
